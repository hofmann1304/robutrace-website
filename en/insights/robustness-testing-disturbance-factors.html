Test strategy

Test disturbance factors systematically instead of trying them at random

Parameter sweeps help teams identify sensitive regions early. This does not require an unmanageable test matrix, but it does require clear prioritisation.

Sara Hofmann·12 June 2026
Stress → Signal

In many projects, parameters are changed until the current image works. This can move a prototype forward quickly, but it does not create knowledge about the stable operating range of the complete system.

Start with the real process

A meaningful robustness analysis does not start with arbitrary image filters, but with observable deviations in the equipment. Typical categories include illumination, focus and blur, part position, sensor noise, occlusion, surface variation and differences between product batches.

Assess disturbance factors separately and in combination

A one-dimensional sweep shows the point at which a metric begins to fail. Combinations are then useful for selected critical regions. This keeps the test volume manageable without ignoring interactions completely.

Do not watch the average alone

At each level, teams should inspect variation, class-specific errors and individual samples alongside the overall score. Cases where small parameter changes cause large result changes are particularly valuable because they mark unstable decision boundaries.

The goal is not the largest possible test matrix, but a traceable map of the stable and critical operating ranges.

A lean test design in five steps

  1. Define process-relevant disturbance factors and realistic value ranges.
  2. Set the nominal state and binding KPI limits.
  3. Run individual sweeps with a few informative levels.
  4. Investigate critical regions with additional measurements and combinations.
  5. Document worst cases, cause hypotheses and actions.

What this creates for engineering decisions

The results can be converted into a test plan, a sensitivity overview and concrete acceptance criteria. This turns trial and error into a repeatable engineering process that can be reused after a variant change or pipeline update.
